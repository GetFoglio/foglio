# Excel function coverage of IronCalc 0.9.1 (Foglio fork)

Foglio uses a patched fork of IronCalc 0.9.1 (`third_party/`, changes listed in
`third_party/README.md`). Generated by `bench/` — re-run with:

```sh
cd bench
cargo run --release --bin functions            # one line per case
cargo run --release --bin functions -- --md    # the tables below
cargo run --release --bin functions -- --locale   # language / locale probe
cargo run --release --bin functions -- --probe '=TEXT(1,"0.0")'   # ad-hoc formulas
```

Each case is evaluated in a fresh `Model::new_empty("t","en","UTC","en")` with a small
fixture (text/number mix, an empty cell, a text "5", TRUE, errors, a sorted lookup
table, a database range — see the comment at the top of `bench/src/bin/functions.rs`),
formula in J10. Expected values are Excel's documented results (Microsoft docs examples
for the financial/statistical functions). A function is **OK** only if all of its cases
match, **MISSING** if it returns `#NAME?`, otherwise **WRONG**.

## Summary

| | IronCalc 0.9.1 | **Foglio fork** |
|---|---|---|
| Tested | 195 | 195 (list order ≈ real-world usage frequency) |
| **OK** | 179 | **191** |
| **WRONG** | 13 | **1** (TREND) |
| **MISSING** | 3 | **3** (AGGREGATE, GROUPBY, PIVOTBY) |
| Cases | 461 / 481 | **476 / 482** |

(One case was added — `POWER(-8,1/2)` is #NUM! — and one expectation corrected:
`POWER(-8,1/3)` is -2 in Excel, see below.)

All the "big" functions (SUM…SUMIFS, VLOOKUP / XLOOKUP / INDEX / MATCH with
wildcards and approximate match, date arithmetic incl. the 1900 leap-year bug,
WORKDAY/NETWORKDAYS(.INTL), financial and statistics functions, dynamic arrays,
LET/LAMBDA/MAP/REDUCE, database functions) match Excel on every edge case tested.

## Fixed in the Foglio fork

| Problem | Formula | Excel | 0.9.1 | Fork |
|---|---|---|---|---|
| Number → text used 17 digits (`&`, CONCATENATE, CONCAT, TEXTJOIN, LEN/LEFT/… on numbers) | `=0.1+0.2&""` | `0.3` | `0.30000000000000004` | `0.3` |
| | `=CONCATENATE(1/3)` / `=LEN(1/3)` | `0.333333333333333` / 17 | 17 digits / 18 | ✓ |
| | `=1E+20&""` | `1E+20` | `100000000000000000000` | `1E+20` |
| Skipped optional argument treated as 0 | `=SORT(A1:A3,,-1)` | sorted desc | `#VALUE!` | ✓ |
| | `=TEXTAFTER("aXb","x",,1)` / `=TEXTBEFORE("a-B","b",,1)` | `b` / `a-` | `#VALUE!` | ✓ |
| | `=TAKE(C1:C6,,1)` (also DROP) | first column | `#CALC!` | ✓ |
| Serial 0 (empty cell) rejected by date parts | `=YEAR(0)`, `=MONTH(0)`, `=DAY(0)` | 1900, 1, 0 | `#NUM!` | ✓ |
| Calendar before March 1900 shifted by a day | `=YEAR(1)` / `=DAY(60)` | 1900 / 29 | 1899 / 28 | ✓ |
| Sign of a zero exponent | `=TEXT(1.5,"0.0E+00")` | `1.5E+00` | `1.5E-00` | ✓ |
| Fraction formats unsupported (TEXT and cell display) | `=TEXT(0.75,"# ?/?")` | ` 3/4` | `  /1` | ✓ (`# ?/?`, `# ??/??`, `?/?`, `# ?/8`) |
| Text argument ignored by AND/OR/XOR | `=AND(TRUE,"a")` | `#VALUE!` | TRUE | ✓ (`""` is still ignored, text in cells too) |

Implementation notes: number → text is `number_format::to_excel_string`
(15 significant digits; scientific from 1E+15 up and when fixed notation would
need more than 18 decimals — Excel itself gives
`VALUETOTEXT(7.123456E-09)` = `0.000000007123456` in IronCalc's Excel-made test
corpus; the exact small-number cut-off is an estimate). Empty arguments:
`functions/util.rs::arg_given`. Fractions: `formatter/format.rs::format_fraction`.

Not a bug after all: **POWER of a negative base with an odd-root exponent**.
The previous audit expected `=POWER(-8,1/3)` → #NUM!, but Excel returns -2
(more precisely -1.9999999999999998: Excel's own cached value in IronCalc's
corpus file `MATH_AND_TRIGONOMETRY/POWER.xlsx`), which is what IronCalc does.
`=POWER(-8,1/2)` is #NUM! in both.

## Still WRONG / MISSING

### AGGREGATE missing (medium)
`=AGGREGATE(9,6,range)` (sum ignoring errors) is a popular idiom. Not in the
function table at all (`#NAME?`). Could be implemented on top of the existing
SUBTOTAL code (`functions/subtotal.rs`) plus the LARGE/SMALL/PERCENTILE/QUARTILE
array forms (14–19).

### TREND with array-constant inputs (low)
`=TREND({1,2,3},{1,2,3},4)` → `#REF!`; with ranges (`=TREND(C1:C3,C1:C3,4)`) it
is correct. Array arguments are not accepted.

### GROUPBY / PIVOTBY missing (low today, rising)
New Excel 365 functions, `#NAME?`.

### Locale in number ↔ text conversions (Italian)
* `=TESTO(1234,5;"#.##0,00")` gives `1.234,5000` instead of `1.234,50`: the
  format string is not de-localized before formatting (see below).
* `=1,5&""` gives `1.5` (Italian Excel: `1,5`): number → text always uses a
  dot (unchanged from 0.9.1; the 15-digit fix above applies). Not changed in
  the fork because criteria code (COUNTIF/SUMIF…) may rely on the dot.

## Other behaviours checked and found correct
Text/number coercion (`"1"+1`, `TRUE+1`, `"2024-01-15"+0`, `10>"9"` is FALSE, empty cell
as 0 / ""), case-insensitive comparisons, `-2^2 = 4`, `0.1+0.2=0.3` is TRUE (15-digit
compare), ROUND half away from zero incl. `ROUND(2.675,2)=2.68`, `ROUND(-1.005,2)`,
INT/MOD/CEILING/FLOOR sign rules, wildcards `*`, `?`, `~` in SUMIF/COUNTIF/MATCH/
VLOOKUP/XLOOKUP/SEARCH, COUNTBLANK counting `=""`, `DATE(1900,3,1)=61`, `DATE(24,1,1)`
→ 1924, month/day overflow, EDATE/EOMONTH end-of-month clamping, WEEKNUM 53,
ISOWEEKNUM, DATEDIF Y/M/D/YM, DATEVALUE in ISO / US / `15-Jan-2024` forms, whole
column references (`SUM(C:C)`).

Not verified (Excel behaviour uncertain, left out of the score): `COUNTIF(range,"5")`
against a text "5" (IronCalc counts it), lenient `DATEVALUE("15/01/2024")` in an en-US
locale (IronCalc accepts it, Excel en-US returns `#VALUE!`), DATEDIF "MD".

## Language and locale support

* **Languages** (function names, booleans, error names): `en`, `it`, `de`, `es`, `fr`
  (from `ironcalc_base/src/language/language.bin`; ids are the bare two-letter codes,
  `it-IT`/`en-US` are rejected).
* **Locales** (`ironcalc_base::get_supported_locales()`): `de`, `en`, `en-GB`, `es`,
  `fr`, `it`. Again bare ids; there is no `en-US` (that is `en`) and no `it-IT`.
* `Model::new_empty("t","it","Europe/Rome","it")` works and behaves like Italian Excel:

| Input | Result |
|---|---|
| `1,5` / `1.234,5` / `15/01/2024` | parsed as 1.5 / 1234.5 / date 45306 |
| `=SOMMA(A1;A3)`, `=SE(A3>1;"sì";"no")`, `=CERCA.VERT(2;A3:A3;1;FALSO)`, `=SE.ERRORE(1/0;"x")`, `=CONTA.SE(A1:A3;">1")`, `=ARROTONDA(2,5;0)`, `=MEDIA(…)`, `=OGGI()`, `=VERO` | all evaluate correctly; `;` is the argument separator and `,` the decimal separator inside formulas (`=1,5+1` → 2,5) |
| `=SUM(A1,A3)` (English name) | `#ERRORE!` — the parser only accepts the active language |
| display | `1234.5` with `#,##0.00` → `1.234,50`; `=OGGI()` → `09/11/2026`; errors `#ERRORE!`, booleans `VERO/FALSO`; default sheet name `Foglio1` |
| `get_localized_cell_content` | returns the formula in Italian (`=SOMMA(A1;A3)`) |

Caveat: `TESTO()`/`TEXT()` format codes must currently be written with English
separators (`"#,##0.00"`); Italian-style codes are mis-rendered (see §3). Formulas are
stored language-neutrally, so a workbook can be switched with `set_language("it")` /
`set_locale("it")` at runtime.
